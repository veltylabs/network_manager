# network_manager
<img src="docs/img/badges.svg">

Network management module for the Velty ecosystem: it makes a site's network **follow its device
inventory**. It stores the site's network settings, asks the router for a plan, shows it together
with who is connected right now, applies exactly the plan the operator reviewed (Apply button with
confirmation) and keeps a history. It knows no router brand: the router arrives as a
`webtyp.com/network.Gateway` (`veltylabs/mikrotik` in production, `network/mem` in tests).

## Quick Start

```go
nm, err := networkmanager.New(db, networkmanager.Deps{
    IDs:       idGenerator,                                           // model.IDGenerator
    Hosts:     devicemanager.NetworkHosts{Devices: dm, TenantID: t},  // network.HostSource
    Importer:  devicemanager.NetworkHosts{Devices: dm, TenantID: t},  // network.HostImporter
    Gateway:   gw,                                                    // network.Gateway (mikrotik.Open(...))
    Publisher: eventPublisher,                                        // optional
    TenantID:  t,
})
nm.MountOperations(reg) // router.OperationRegistry
// Screens (ui/): Browser (Red), PlanBrowser (Cambios pendientes, with Apply),
// ConnectionsBrowser (Conectados), HistoryBrowser (Historial de red).
```

Schema: `migrate.Migrate(conn, compiler)` from the app's migration binary.

## Demo

Run `webtyp` at the repository root: in-browser, in-memory gateway with two connected devices and
one hand-made rule, no login.

## Key files

| File | Purpose |
|---|---|
| `model.go` | Definitions, constants, errors, event topic |
| `kinds/` | The `unregistered` radio (own package, for ormc) |
| `model_orm.go` | Generated by `ormc` — do not edit |
| `module.go` | `Module`, `New`, services (settings, plan, apply, connections, discover, import, history) |
| `ops.go` | `router.OperationModule` — `MountOperations` + handlers |
| `view.go` | The four presenters; the plan presenter declares the Apply action |
